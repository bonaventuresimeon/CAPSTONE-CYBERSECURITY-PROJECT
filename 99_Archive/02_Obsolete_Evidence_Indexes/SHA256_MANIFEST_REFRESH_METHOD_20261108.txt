CAPSTONE PROJECT 138 — SHA-256 MANIFEST REFRESH METHOD
Date: 8 November 2026 (Africa/Lagos)

Purpose:
Preserve the pre-consolidation SHA-256 manifest and regenerate the project manifest after the new discovery, vulnerability, risk, control, GRC, cloud, reporting and governance documents were written.

Procedure:
1. Copy the current 8 November 2026 manifest to 99_Archive\02_Obsolete_Evidence_Indexes\SHA256_EVIDENCE_MANIFEST_PRE_WORKSTREAM_DOCS_20261108.csv.
2. Enumerate project files recursively under the project root.
3. Exclude the active manifest from its own manifest (self-hashing is not possible) and exclude generated .dist folders.
4. Calculate SHA-256, file length and last-write timestamp for each included file.
5. Sort by relative path and write the refreshed CSV to 09_Evidence\SHA256_EVIDENCE_MANIFEST_20261108.csv.
6. Independently re-read the CSV and recompute every listed file hash; check duplicate relative paths and missing paths.
7. Record the resulting counts and active manifest hash in the documentation handoff.

No target, VM, network, service, package or cloud configuration is changed by this evidence-index procedure.
